# Документы дипломного проекта

Общие ТЗ и ПМИ и индивидуальный комплект одного автора. Все документы используют библиотеку оформления `template/`.

## Начать работу

1. Откройте **всю папку репозитория** в редакторе.
2. Откройте главный файл нужного документа из таблицы ниже.
3. В VS Code запустите превью Tinymist и закрепите его за этим `main.typ`.
4. Пишите в файлах его папки `sections/`, заменяя строки-заглушки и удаляя выполненные комментарии TODO. Превью обновляется автоматически.

| Документ | Главный файл | PDF после экспорта |
|---|---|---|
| Общее ТЗ | `common/tz/main.typ` | `build/common-tz.pdf` |
| Общая ПМИ | `common/pmi/main.typ` | `build/common-pmi.pdf` |
| Индивидуальное ТЗ | `individual/tz/main.typ` | `build/individual-tz.pdf` |
| Индивидуальная ПМИ | `individual/pmi/main.typ` | `build/individual-pmi.pdf` |
| Пояснительная записка | `individual/explanatory-note/main.typ` | `build/explanatory-note.pdf` |
| Текст программы | `individual/program-text/main.typ` | `build/program-text.pdf` |
| Руководство программиста | `individual/programmer-guide/main.typ` | `build/programmer-guide.pdf` |

В каждой папке документа `main.typ` задаёт порядок разделов, `metadata.typ` — его реквизиты, `sections/` — заголовки и текст. Например, `01-introduction.typ` — введение, `04-software-requirements.typ` — требования к программе. Один главный файл собирается в один PDF.

## Где менять реквизиты

| Что меняется | Файл |
|---|---|
| Тема общих ТЗ и ПМИ | `shared/titles.typ` → `common-title` |
| Тема индивидуального комплекта | `shared/titles.typ` → `individual-title` |
| Организация, руководители, город, год, исполнители общих документов | `shared/project.typ` |
| Автор индивидуальных документов | `shared/people.typ` |
| Префикс обозначений документов | `shared/project.typ` → `designation` |
| Вид документа, суффикс обозначения и особые реквизиты | `metadata.typ` конкретного документа |

Темы двух комплектов независимы. Чтобы задать отдельную тему одному документу, замените значение `title` в его `metadata.typ`.

**Реквизиты пока из прошлогоднего образца:** тема, ФИО, группа, руководители, год, обозначения и два исполнителя общих документов. Их нужно актуализировать. Заголовки про AST, LLVM и другие части прошлого проекта также являются редактируемой заготовкой, а не утверждённым составом диплома.

## Экспорт

На Windows через PowerShell, без Python:

```powershell
./build.ps1 individual-tz
./build.ps1 all
./build.ps1 -List
```

На любой ОС с Python 3 и Typst CLI:

```sh
python build.py individual-tz
python build.py all
python build.py --list
```

Если команда Python называется `python3`, используйте её. Скрипты читают один список `documents.json`; PDF записываются в `build/`. Идентификатор документа совпадает с именем PDF без расширения.

Компилятор ищется в PATH; на Windows поддерживается также установленный Tinymist из расширений VS Code. Для нестандартного расположения есть `-Compiler` у PowerShell-скрипта и `--compiler` у Python-скрипта. Экспорт прекращается при ошибке.

При ручной сборке задавайте корень проекта; папка `build/` должна существовать:

```sh
typst compile --root . common/tz/main.typ build/common-tz.pdf
```

Скрипт не нужен при каждом изменении текста: для написания используйте живое превью.

## Редактор и шрифты

VS Code предлагает расширение Tinymist через `.vscode/extensions.json`. В `.vscode/settings.json` корень Typst задан как `${workspaceFolder}`. Поэтому открывайте всю папку репозитория, а не отдельную папку документа. В другом редакторе настройте тот же корень.

Нужен Times New Roman с обычным, жирным, курсивным и жирным курсивным начертаниями. На разных ОС должны использоваться одинаковые файлы шрифтов и версия Typst. Шрифты в репозитории не распространяются. Проверено на Windows с Typst 0.15.1 в Tinymist 0.15.12; сборка на других ОС пока не проверялась.

## Библиотека оформления

- `template/document.typ` — оформление основного текста и служебные страницы вокруг него.
- `template/covers.typ` — лист утверждения и титульный лист.
- `template/geometry.typ` — колонтитулы и инвентарные таблицы.
- `template/components.typ` — содержание, ненумерованные заголовки, приложение и лист регистрации изменений.

Разделы документа подключаются в его `main.typ`; библиотека не задаёт их состав. У «Текста программы» нет содержания, как в образце. У ПЗ есть раздел о генеративных моделях и приложение — ненужные части можно отключить, удалив соответствующие `include`.

Подробнее о геометрии страниц и ещё не реализованных правилах: [оформление и ограничения](docs/formatting.md).

## Контроль изменений

В Git хранятся исходники, настройки, инструкции и скрипты. `build/` и временные файлы исключены через `.gitignore`; исходные PDF и иллюстрации при необходимости можно хранить в отдельных папках ресурсов.

Перед коммитом просмотрите `git diff`. После изменения общей библиотеки соберите весь комплект. Изменения текста и общих стилей удобно сохранять отдельными коммитами.
